# Description
Enforces strict Conventional Commits formatting and confidentiality rules for all version control changes.

# Instructions
When making code changes or committing to Git, you must:
1. Always use Conventional Commits (e.g., feat:, fix:, docs:, refactor:).
2. Scope the commit to the specific module (e.g., feat(api): or fix(graph):).
3. Provide a concise, imperative present-tense description.
4. Strictly ensure the name of the hiring company is never used. Use "Company Z" for any necessary documentation or mock data context.
